Why the driver becomes corrupted
  1. An OutOfMemoryError lands during a wire request's write path.
  2. The server reply is not fully consumed, but the connection is returned to the pool.
  3. The next operation reuses the connection and reads the stale reply.
  4. The responseTo mismatch desynchronizes the stream.

Read safeguard: driver 4.9.1 clears dirty state for read requests; the write-request fix is tracked in JAVA-6210.

What the replay demonstrates

The first visible failure is not the first causal event.

The archive request creates memory pressure; the monitoring OOM and driver corruption form the bridge between that pressure and the later backup failure. The final abort is the agent's defensive response.
