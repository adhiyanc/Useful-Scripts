MongoDB FTDC reporter

One Python script to decode raw FTDC and print a usable performance report.

This script reads raw metrics.* files or a full diagnostic.data directory, decompresses FTDC type 1 chunks in pure Python, extracts only the fields it needs, and prints an operator-friendly report covering op counts, latencies, memory, CPU, and WiredTiger cache behavior.

What it does

It replaces the awkward two-step FTDC workflow with one CLI entry point.

The script combines FTDC decoding and report generation. For raw FTDC it parses BSON, inflates compressed type 1 chunks, reconstructs sample deltas, flattens only the target paths, then prints a Markdown-style report. For decoded JSON it follows the same summary path for parity.

Why it exists

  • bsondump alone does not fully solve FTDC metric-chunk decoding.
  • Operators usually want a quick, readable window summary rather than raw samples.
  • The script keeps the workflow local, dependency-light, and repeatable.

What it prints

  • timeframe summary and sample cadence
  • opcounter deltas
  • op latency throughput and averages
  • memory, CPU, and page-fault metrics
  • WiredTiger cache occupancy and flow
  • snapshot envelope boundaries
Input modes

One interface, three supported sources.

Use the same script against raw FTDC archives or already-expanded JSON snapshots. Switch between the modes below.

Single raw metrics file

Point the script directly at one metrics.<timestamp>-00000 file. It reads outer BSON documents, selects type 1 docs, decompresses chunk payloads, and reconstructs metric samples.

python3 ftdc_metrics_report.py /path/to/metrics.2026-05-11T04-19-11Z-00000

diagnostic.data directory

Point the script at the directory. It sorts all metrics.* files, skips metrics.interim, and processes the archive as one continuous stream.

python3 ftdc_metrics_report.py /path/to/diagnostic.data

Decoded JSON snapshots

Use this for parity testing or when you already have concatenated JSON snapshots. The script auto-detects .json input, or you can force it with --decoded-json.

python3 ftdc_metrics_report.py /path/to/xaa.json python3 ftdc_metrics_report.py /path/to/snapshots.txt --decoded-json
Decode pipeline

From raw FTDC chunk to report row.

The raw path is intentionally narrow: it only reconstructs the metric fields needed for the report, which keeps it efficient and easier to reason about.

Enumerate inputs

If the input is a directory, gather sorted metrics.* files and skip metrics.interim. Otherwise process the single file as-is.

Decode outer BSON documents

A minimal built-in BSON decoder walks the file and yields outer FTDC docs without requiring external packages.

Keep only type 1 metric chunks

Non-type-1 docs are ignored on the raw path. For each type 1 doc, the script reads the raw binary data payload.

Inflate and reconstruct deltas

The first 4 bytes are skipped, the remaining payload is zlib-inflated, the reference BSON document is decoded, and the varint delta stream is replayed across all metrics.

Flatten only target paths

The script keeps a fixed target-path list for timestamps, opcounters, opLatencies, memory, extra_info, WiredTiger cache fields, and CPU aliases.

Build window summary

Sample rows are summarized into timeframe, delta, throughput, average, and cache/CPU ratios, then printed as Markdown-style tables.

How key calculations work

The script turns cumulative counters into window metrics.

These are the core interpretations behind the report output.

Latency

window_avg_latency_ms = (last_latency_us - first_latency_us) / (last_ops - first_ops) / 1000 throughput_ops_per_s = (last_ops - first_ops) / elapsed_seconds

MongoDB stores cumulative op latency in microseconds. The script calculates the per-window average from the delta and converts the result to milliseconds for display.

CPU

cpu_pct = (delta_counter_ms / delta_time_ms) * 100 cpu_normalized_pct = cpu_pct / cores

Aggregate CPU percentages can exceed 100% on multi-core systems. The normalized values divide by detected core count to show per-core utilization.

Cache fill ratio

cache_fill_ratio_pct = (bytes_currently_in_cache / maximum_bytes_configured) * 100

This gives a direct occupancy view of the configured WiredTiger cache.

Page faults and context switches

window_delta = last_cumulative_value - first_cumulative_value avg_per_second = window_delta / elapsed_seconds

The script treats these as cumulative counters and reports both the total change over the window and the per-second average when useful.

Usage

Run it exactly like a normal CLI tool.

The script requires an explicit input argument and decides between raw FTDC and decoded JSON based on the path or the optional switch.

Examples

python3 ftdc_metrics_report.py /path/to/metrics.2026-05-11T04-19-11Z-00000 python3 ftdc_metrics_report.py /path/to/diagnostic.data python3 ftdc_metrics_report.py /path/to/decoded.json python3 ftdc_metrics_report.py /path/to/snapshots.txt --decoded-json

Expected output shape

  • plain text report
  • Markdown-like tables for easy copy/paste into tickets or notes
  • no file artifacts written by the script itself
  • stdout-friendly for shell redirection if needed
Limits and caveats

Interpret the output with the right assumptions.

The script is intentionally practical, but a few limits matter when reading the report.

CPU is conditional

CPU metrics appear only when the FTDC input includes systemMetrics.cpu. A serverStatus-only JSON export can still produce memory and cache sections while leaving CPU unavailable.

Type 1 only on the raw path

The raw FTDC summarizer focuses on type 1 metric chunks and ignores non-type-1 documents for the reporting path.

Latency is an average, not a percentile

The latency section reports average per-op latency derived from cumulative counters. It does not estimate p95 or p99 latency.

Field coverage is targeted

The decoder reconstructs only a fixed target-path set. It is optimized for this report, not as a general FTDC explorer.

Best use case: quick support triage and performance window analysis from raw FTDC, without first building a separate decode pipeline.
