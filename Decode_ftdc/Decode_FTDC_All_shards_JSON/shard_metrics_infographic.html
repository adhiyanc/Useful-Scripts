Execution flow

The script does the same sequence for every target shard, using one worker per target.

1

Validate inputs

Checks time formats, ensures the directory prefix is absolute, and rejects an end time earlier than the start time.

2

Read helper script

Loads decode_helper_py36.py into memory so the exact script body can be streamed to each host.

3

Build metrics path

Constructs the remote directory as <prefix>/<shard>/data/diagnostic.data.

4

Run remote decode

Uses SSH to run python3 - with shard, dir, start, and end arguments on the remote host.

5

Aggregate outputs

Saves per-shard JSON, then writes a combined JSON file and a flattened CSV built from each shard's metrics.

What you need to provide

These are the minimum inputs required for a clean run.

PRIMARY_TARGETS Environment variable with shard and host pairs +

The script reads target hosts from PRIMARY_TARGETS using ast.literal_eval().

It expects a Python-style list of tuples:

[('shard01','host1.example.com'),('shard02','host2.example.com')]
--start and --end Inclusive time window for the decode helper +

Accepted input styles:

  • Epoch milliseconds
  • UTC ISO-8601 ending in Z
  • YYYY-MM-DD HH:MM:SS
  • YYYY-MM-DD HH:MM
  • YYYY-MM-DD
2026-07-07T10:00:00Z "2026-07-07 10:00" 1751872800000
--dir-prefix Absolute base path for every shard directory +

This must start with a slash and cannot be empty.

Example:

/d/d3/sem2/qa

The script appends <shard>/data/diagnostic.data automatically.

Remote host prerequisites What must already work on each target machine +
  • SSH connectivity from the machine running this script
  • python3 installed remotely
  • Access to the computed diagnostic data path
  • A helper that writes valid JSON to stdout

Run it

Use this as the operator path: set targets first, then execute with a time range and directory prefix.

export PRIMARY_TARGETS="[('shard01','host1.example.com'),('shard02','host2.example.com')]"

python3 collect_metrics.py \
  --start 2026-07-07T10:00:00Z \
  --end 2026-07-07T11:00:00Z \
  --dir-prefix /d/d3/sem2/qa
The helper is sent over standard input to the remote host and executed as python3 -.

Troubleshooting map

Hover and expand these cards when something fails. Each one ties the symptom to the likely fix.

--dir-prefix must be an absolute path Validation failure before any remote work starts +

You passed a relative path. Use a full absolute base directory such as:

/d/d3/sem2/qa
remote stdout was not valid JSON The helper printed non-JSON content to stdout +

Inspect the saved shard file under shard_outputs/<shard>.json. The helper should emit clean JSON only on stdout.

ssh/remote command failed Transport or remote execution failure +
  • Test SSH manually
  • Confirm python3 exists on the host
  • Check the computed diagnostic data directory
  • Review captured stderr in the saved shard JSON
Empty CSV No usable metrics were returned +

This usually means either no shard returned valid data or the decoded metrics map was empty.

Pre-run checklist

Use this checklist before you start a real collection run.

Local side

Everything on the machine where you launch the script.

  • decode_helper_py36.py is present
  • PRIMARY_TARGETS is valid Python literal syntax
  • You know the correct start and end times
  • The base prefix path pattern is correct

Remote side

Everything that must work on each shard host.

  • SSH is reachable
  • python3 is installed
  • The shard directory exists at the computed path
  • The helper can read the diagnostic data directory

Keep in mind

The code already contains a local execution path, but it is commented out. The active behavior is remote SSH execution only.

Current behavior Remote decode via ThreadPoolExecutor and SSH
Optional future tweak Switch the submitted worker to run_local_decode for local-only testing
